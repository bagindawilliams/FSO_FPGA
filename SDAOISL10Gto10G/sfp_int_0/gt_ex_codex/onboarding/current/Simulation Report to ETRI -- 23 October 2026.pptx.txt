   ARQ Selective Repeat



The initial development of the Automatic Repeat
Request (ARQ) system was based on SDA OISL
Standard v2.1.2, particularly for the frame header
structure, ARQ configuration parameters, and
acknowledgement (ACK/NAK) signaling.

During further development, SDA OCT Standard
v4.0.0 was adopted as an additional technical
reference to clarify the operational aspects of ARQ,
including frame identification, retransmission control,
buffer management, and in-order frame delivery.

  Module for Scrambler –
  Module for Scrambler
Scrambler Data
The scrambler randomizes the bit sequence before transmission. Its purpose is to avoid long, consecutive
strings of '0' or '1' bits, maintaining Direct Current balance and ensuring successful clock recovery on the
receiving device (GTH Transceiver).




The randomization process is carried out through a pure XOR logic operation between the 64-bit input data
(data_in_d0) and the active PRBS state vector (S). For each pair of bytes entering the scrambler, the bits shall
enter the scrambler in the order byte 0 (MSB) to byte 1 (LSB).

  Module for LPC (24,16)
LPC Data
LPC serves as a secondary layer Forward Error Correction (FEC) mechanism after Reed-Solomon. This
compression method detects and corrects additional bit errors that may occur during optical
transmission.


                                                    Distributes the 64-bit bus of the Scrambler into
                                                    four parallel lines of 16 bits each. These four
                                                    lines are processed simultaneously by four
                                                    instances of the lpc submodule (lpc_3 to lpc_0).

                                                    In each lpc.v sub-module, the 16-bit input is first
                                                    mapped into the encryption component of the matrix
                                                    E[0:15]. Then, the module computes the Horizontal
                                                    (H[0:3]) and Vertical (V[0:3]) vectors using
                                                    high-speed cascaded linear XOR equations.

3 Operational Zones:

Zone 1 – Preamble & Header Protection -> For the first 15 words (60 bytes = Byte 1 to Byte 60), which includes 9 bytes of preamble +
48 bytes of LPC header + 3 bytes of margin

Zone 2 – Payload Error Injection -> From word 16 to word 63 (48 words = 192 bytes, i.e., Byte 61 to Byte 252), the module reads 48
lines of the garbled pattern from error.mem and XORs them with the payload data.

Zone 3 – Payload Remainder Pass-Through -> From word 64 to byte 3117 (the remaining 2865 bytes, i.e., Byte 253 to Byte 3117), the
data Pass-Through. Right on reaching Byte 3117, the FSM immediately rolls back to Zone 1 (IDLE) to protect the Preamble of the next
frame without ever dropping the gth_tx_valid_out signal.
